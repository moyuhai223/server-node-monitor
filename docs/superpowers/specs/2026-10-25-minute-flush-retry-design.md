# MinuteFlush 持久化失败重试修复（P1-1）

设计已由用户于 2026-10-25 确认。范围仅限审查项 P1-1，不修改其他四项问题、主题、协议或生产数据；不自动提交、推送或发布。

## 方案

采用“事务成功后确认移除”而非“失败后恢复 rollover 列表”。在全局 DbWriteLock 下串行化 flush 的收集、快照、写入和确认，避免重叠 flush 把同一快照处理两次。节点快照仍在 node.Sync 下获取；PendingDays 和 PendingClosed 在提交前保留原条目。事务提交后只移除本次成功写入的快照条目，不清空 flush 期间新增的 rollover。快照时清除的 Dirty 标记不会在提交确认时再次清除，因此并发心跳仍会触发下一次 flush。

任何提交前异常（含取消）均重新入队本次 metric rows，并在节点锁下恢复 traffic/state dirty 标记。取消异常恢复后继续抛出。日/账期仍按绝对累计值 upsert；失败事务回滚后重试不会重复累计。

## 验收

隔离 SQLite 注入保存失败、提交失败和取消，验证旧日/旧账期仍待处理，重试后对应记录及累计值完整；再 flush 不重复计数。暂停保存并并发推进日/账期，验证提交确认不误删新增条目或脏标记。覆盖 metric rows、节点状态和并发 flush。新回归测试应先在原始源码失败、再在修改源码通过；回滚副本复现原始行为，恢复哈希必须等于原始哈希。
